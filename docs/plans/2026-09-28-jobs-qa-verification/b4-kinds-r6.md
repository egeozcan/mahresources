### P2 — A failed live Apply loses both its failure notice and a result-read error under infrastructure faults

**Locations:** `src/components/adminImport.js:905`–`:909` clears the known terminal error before starting the result read; `:940`–`:955` returns silently for a non-404 error or catches a rejected/undecodable response. Related presentation: `templates/adminImport.tpl:385`, `:404`, `:425`, and the error alert at `:50`.

**Concrete scenario:** an Apply accepted on this page emits its own `status=failed` SSE event with an honest failure message. The result GET then returns HTTP 500, rejects because the network is offline, or has an undecodable successful response. R6 leaves `applying=false`, `applyJobId` set, `applyResult=null`, `applyOutcome=''`, `error=null`, and no Apply stream. The progress region and Apply button are hidden, and neither the known Job failure nor the failed result read is shown. The canonical Job remains available through Jobs, so work and its durable outcome are not lost.

**Read:** the entire live acceptance/SSE/result/cancel flow, all result state assignments, the alert/progress/result template conditions, and the corresponding `e90c76b6` source. **Ran:** `review-r6-provenance-ui.mjs` compares actual R6 and a scratch copy of the previous head using the same visible failed terminal event and each of the three explicitly injected read faults. The successful actual-API result and accepted-ID mismatch cases in the same probe still behave correctly. These fault assertions are diagnostic reproductions, not desired-behavior regression passes.

**Suggested fix:** handle result read failures as a separate, generation-owned read-error notice. A 404 may keep the visible live Job's honest failure with no report. A 200 response with unknown/mismatched producer must retain its unknown outcome and must not inherit the old Job's failure. For non-404/network/decode failures, announce that the report could not be read and give the reader a way to follow the accepted Job; keep that notice distinct from any report's success/failure. Add focused cases for these fault branches. Grade P2 under the explicit infrastructure-fault/workaround portion of the rubric. This is introduced by `4254179f`'s terminal clearing, rather than inherited from the prior head.
