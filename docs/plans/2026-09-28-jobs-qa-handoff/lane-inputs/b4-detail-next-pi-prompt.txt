## Previously declined, with evidence
- "P1: Job page titles can still be identical because the short id keeps eight hex characters" (jobs/short_id.go, jobCenter.js shortJobId). Declined as P1. Two titles collide only for two Jobs with the same title, the same state and the same last 32 random bits of their UUIDv7 ids. The title exists so a person can tell apart the Job pages they have open or just visited (typically a retry chain of a few attempts); for any two given Jobs the chance is 1 in 4.3 billion, and the birthday figure over 77,000 same-title Jobs describes no set of pages anyone has open. By the rubric's consequence test it is at most P2 (confusing but survivable, with a workaround: the full id is printed in the page header under the heading). The full 36-character id in every document title would be read aloud on every page load by screen readers and truncated away in tab strips, which costs every reader for a case that does not arise. If you still see a P1 here, give a scenario a real user reaches, not a population statistic.
